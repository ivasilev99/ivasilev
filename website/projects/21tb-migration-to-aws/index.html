21 TB database move to AWS

I moved 21 TB of database files from on-prem servers to AWS. S3 cannot store hard links, so I packed the data into tar chunks, carried them through S3 and unpacked them on EC2 with every link intact.

  • tar chunks carried through S3
  • hard links kept intact
  • 1:1 size after restore
Where
PROS Bulgaria
Role
Site Reliability Engineer II
Stack
  • Bash
  • tar
  • Amazon S3
  • Amazon EC2

The problem

The databases had to move to EC2 by way of S3, but their files rely on hard links. S3 stores plain objects and has no idea what a hard link is, so uploading the files directly would have turned every link into a separate full copy and blown up the data set.

How I did it

  1. Packed the data into tar archives split into chunks. tar records a hard link as a link, not as a second copy of the file.
  2. Uploaded the tar chunks to S3, which served as the transfer point between on-prem and AWS.
  3. Downloaded the chunks onto the EC2 machine and unpacked them there, which rebuilt every hard link exactly as it was.
  4. Checked that the restored data matched the source size, then started the databases from it.

Why tar. S3 can carry the bytes but not the links between files. tar wraps the links inside the archive, so they survive the trip and come back when it is unpacked.

Result

The databases came up on EC2 with every hard link intact and the same size as the source.
